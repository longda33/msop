三个界面，九套方案

启动画面、音乐库「沙漏」筛选弹窗、退出确认弹窗——沿用现有的深空墨底 + 极光紫 + 玻璃卡语言， 每个界面给三套方向。点右上角可切换深色／浅色两套主题预览，两套都做了适配。

界面内动画均为真实循环演示，非静态图
启动画面 · 现状 只有 windowBackground 一层纯色，冷启动是「黑屏 → 曲库突然出现」，没有品牌露出，首次扫描的等待也无处安放。
沙漏弹窗 · 现状 右上角 PlayerIcons.Filter 锚定原生 DropdownMenu，三行纯文字，位于单手最难够到的角落；筛选后除「歌曲」页外看不出变化。
关闭弹窗 · 现状 目前没有确认弹窗，返回键直接退栈。播放器里「退出」通常意味着停播，需要一次轻确认，但不应变成拦路的表单。

极光呼吸

  • 风险最低：不依赖封面、不依赖数据，首装与老用户完全一致。

方案 B

唱片落针

近乎全黑的画布，只留一张持续旋转的黑胶和一束侧光，把「开始听」做成一个动作。

  • 情绪最强：和播放器的唱片隐喻直接呼应，老用户会有认同感。
  • 代价：1.2s 内演完，冷启动偏慢时会有「演完了还在等」的尴尬。

方案 C

声波索引

七根竖条从中心向两侧依次点亮，像音频可视化，同时把初始化进度讲清楚。

  • 文案随阶段变化：整理曲库 → 合并重复 → 就绪，三步小横条跟随。

  • 代价：最「技术」，品牌温度不如 A / B；也最依赖初始化状态是否可靠。

方案 C

标题内联分段器

不弹窗。点沙漏，标题下方滑入一条分段控件，滑块跟手；右侧常驻当前条数，再点沙漏收起。

  • 代价：永久占掉一行高度（约 44dp），列表首屏少半行。

玻璃确认卡

居中 232dp 玻璃卡：52dp 圆形图标 + 标题 + 两行说明 + 主次按钮。

  • 主次分明：主按钮「继续听」紫渐变实心，次按钮「退出」只留红字。

  • 误触成本低：默认动作是留下，退出需要精准点到右侧。

方案 C

极简一问

200dp 无图标小卡，一行问句 + 一行灰字 + 两枚等宽胶囊，不做任何解释性排版。

  • 最快：一眼看完，两个动作一目了然。

  • 代价：信息少，用户可能不确定退出是否等于停播。

我的建议组合

01启动 A · 极光呼吸 02沙漏 C · 内联分段器 03关闭 A · 玻璃确认卡

启动选 A：品牌露出、情绪、成本三项都不踩雷；B 更适合做「首次安装」的一次性引导，不适合每次冷启动都播。

沙漏选 C：你上一轮报的「只有歌曲类目生效」本质是状态不可见，C 把状态常驻在标题下方，比任何弹窗都直接。若舍不得那一行高度，退一步选 A（底部浮卡），条数和说明也够用；B 只建议作为「一天内的最小改动」。

关闭选 A：退出前必须让人知道「音乐会停」，A 用一句话讲完又不啰嗦；C 太轻，B 太重。

落地时要注意的两件事。
一、Android 12+ 会先弹系统 SplashScreen（背景取 windowBackground、前景取应用图标），自定义启动画面只能在它之后接管。 三套方案都建议把 windowBackground 设为 #07080D，并让系统图标前景与方案中央符号保持同一图形，否则会出现「双启动图」跳变。
二、现在右上角其实是漏斗（PlayerIcons.Filter），不是沙漏。若选方案 C，建议换成真正的沙漏，并在筛选生效时做一次 180° 翻转——翻转本身就是「正在过滤」的状态提示。
