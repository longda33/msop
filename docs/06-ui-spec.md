# 06 — UI 规范

> 状态：**草案 · 未确认**（2026-11-10）。本文件只是讨论稿，**不得据此写代码**。
> 原则：结构优先于配色。所有颜色走 Material 3 动态取色，不在代码里写死色值。

## 1. 信息架构

```
底部导航（3 Tab）
├── 音乐库
│   ├── 歌曲        ← 默认落地页
│   ├── 专辑
│   ├── 艺术家
│   └── 文件夹
├── 搜索
└── 设置
    ├── 本机目录管理
    ├── OpenList 服务器
    ├── 播放（仅 Wi-Fi 预加载 / 均衡器）
    └── 存储（缓存清理）

全局浮层
├── 迷你播放条    ← 有播放内容时常驻于底部导航之上
└── 播放页        ← 点迷你条上滑全屏，下滑收起
    ├── 封面模式
    ├── 歌词模式
    └── 播放队列（上滑面板）
```

**导航原则**：
- 播放页是 **overlay sheet，不是独立路由**，不进入返回栈。这样「返回」永远等于「收起」，不会出现返回键把用户从播放页弹回列表的怪行为。
- 详情页（专辑/艺术家/本机目录/服务器配置）是独立路由，正常入栈。

## 3. 设计令牌

### 3.1 间距（dp）

| 用途 | 值 |
|---|---|
| 屏幕左右边距 | 16 |
| 列表项内边距 | 8 上下 / 16 左右 |
| 分组之间 | 24 |
| 元素之间 | 8 |
| 紧凑间隙 | 4 |

### 3.2 字号（sp）

| 层级 | 字号 / 字重 | 用途 |
|---|---|---|
| Display | 20 / 500 | 页面标题（音乐库、设置） |
| Title | 14 / 500 | 列表项主标题、播放页标题（播放页用 20） |
| Body | 13 / 400 | 正文、歌词非当前行 |
| Caption | 11 / 400 | 时长、计数、辅助说明 |
| LyricActive | 15 / 500 | 歌词当前行 |

### 3.3 圆角（dp）

| 元素 | 值 |
|---|---|
| 列表小封面 | 6 |
| 网格专辑封面 | 10 |
| 播放页大封面 | 12 |
| 卡片 / 面板 | 12 |
| 芯片 | 全圆角 |

### 3.4 颜色

- 全部使用 `MaterialTheme.colorScheme`，**不写死十六进制**
- 跟随系统深色模式；Android 12+ 启用动态取色
- 语义色只用于三处：连接成功（success）、明文警告（warning）、清理缓存（danger）
- **来源标识不用颜色区分**，用图标或文字，避免列表出现彩色噪音

## 5. 关键交互

| 操作 | 行为 |

## 6. 边界状态（必须实现）

| 状态 | 表现 |
|---|---|
| 首次启动、无权限 | 整页引导：说明用途 + 「授予权限」按钮 |
| 已授权但库为空 | 空状态：提示「没找到音乐」+ 「添加目录」+ 「配置 OpenList」 |
| 扫描进行中 | 顶部细进度条 + 列表实时追加（不阻塞浏览） |
| OpenList 未配置 | 云端筛选芯片置灰，点击跳到配置页 |
| 连接失败 | 红色条 + 具体错误（DNS / 证书 / 401 / 超时） |
| 断网播放远程 | 提示「网络不可用」+ 暂停，恢复后不自动续播（避免误流量） |
| 缓存已满 | 静默 LRU 淘汰，不弹窗 |

## 7. 明确不做的 UI

- 不做开屏动画、启动引导轮播
- 不做「正在播放」全屏模糊背景（性能与实现成本不值）
- 不做歌单封面自定义
- 不做歌词翻译、逐字歌词
- 不做桌面小组件、通知栏大图（P5 之后再议）

## 9. Primuse UI 还原度评估（实测依据）

**证据来源**：仓库 `Views/` 下 312 个 Swift 文件、11.9 MB UI 代码；官方 iOS 截图 10 张（已下载到 `docs/reference/primuse-ios/`）。

### 9.1 三层分档

| 层 | 内容 | 还原度 | 说明 |
|---|---|---|---|
| **骨架层** | 歌曲列表、专辑网格、艺术家、搜索、设置 | **88–92%** | Compose 布局能力完全够，差异只在图标与字体 |
| **播放层** | 大封面、进度条、控制键、歌词滚动 | **78–85%** | 毛玻璃与动效打折，其余可复刻 |
| **特效层** | 沉浸式舞台、Liquid Glass 背景、逐字卡拉OK | **30–50%** | Metal shader 视觉特效，Android 需重写 |

### 9.2 为什么特效层做不到

Primuse 的播放页不只是 UI，里面塞了一整套 GPU 着色器视觉系统：

```
ImmersiveStageView.swift        131 KB
ImmersiveStageScenery.swift      89 KB
ImmersiveKineticShaderSource.swift 71 KB
ImmersiveSimulationRenderers.swift 44 KB
ImmersiveKineticMetalBackdrop.swift 33 KB
LiquidArtworkBackdrop.swift       9 KB
```

合计约 **377 KB 的 Metal / SwiftUI 特效代码**。要在 Android 复刻需改用 AGSL（API 33+）或 Vulkan，工作量以月计，且低端机会掉帧。**建议直接砍掉。**

### 9.3 iOS 元素逐个对照

| iOS 元素 | Android 现状 | 还原度 | 对策 |
|---|---|---|---|
| SF Symbols 图标 | Material Symbols 形状语汇不同 | **75%** | 逐个挑近似图标，少数需自绘 |
| SF Pro / 苹方 | 可打包近似字体，字形仍不同 | **80%** | 用系统默认字体，别硬塞 |
| 毛玻璃 material | Compose 无原生模糊，需 `RenderEffect`（API 31+） | **65%** | 用半透明纯色替代，性能优先 |
| Liquid Glass | 无对应物 | **50%** | 模拟高光描边，效果有限 |
| Sheet 分档高度 | `ModalBottomSheet` 近似 | **85%** | 可用 |
| 弹簧动画曲线 | Compose `spring()` 可调 | **90%** | 基本一致 |
| 边缘滑动返回 | 与 Android 系统手势冲突 | **70%** | 放弃，用系统返回 |
| 大标题折叠导航 | 需手写 collapsing toolbar | **85%** | 可用 |
| 胶囊浮动播放条 | Compose 可做 | **95%** | 可用 |
| 圆形 FAB 搜索 | Compose 可做 | **95%** | 可用 |
| 逐字卡拉OK歌词 | 需自己算音节时间轴 + 逐字动画 | **60%** | 工作量 2–3 周 |
| 动态封面 | Coil + 动画可做 | **85%** | 可用 |

### 9.4 结论

- **核心 5 屏（歌曲 / 专辑 / 播放 / 歌词 / 设置）走 B 路线可到 85% 神似**，截图对比第一眼难分辨，细看能看出是安卓。
- **追到 95% 不划算**：要多花 3–4 周，且 SF Symbols 与字体差异无法消除，仍然会被一眼认出。
- **路线 A（像素级复刻）不推荐**：iOS 原生设计硬搬到 Android，会和系统返回手势、Material You、通知栏规范打架，用起来别扭。
- **路线 B（推荐）**：保留 Primuse 的**信息架构 + 视觉语言**（深色播放页、大封面、胶囊播放条、圆角卡片），但组件用 Material 3 实现。用户感知是"同一个设计语言"，而不是"一个不像安卓的安卓 App"。
